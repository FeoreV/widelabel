# ADR-005: Medusa Inventory Reservation Transaction Boundaries

## Status
Accepted

## Context
WIDE LABEL sells unique 1-of-1 physical items. Each item has exactly `inventory_quantity = 1`. When a customer adds an item to cart, it must be reserved for 15 minutes. We must guarantee that no two customers can hold or purchase the same item concurrently under high traffic (drop scenarios).

## Spike Findings
1. Medusa core inventory module tracks stock levels, but domain-specific reservation rules (15-min TTL, idempotency per cart, automatic expiration) require strict database-level constraints.
2. Redis lock alone is insufficient as Redis TTL does not change durable domain state and could lead to race conditions if Redis key expires or fails.
3. PostgreSQL transaction boundary with partial unique index `uq_wl_one_open_reservation_per_variant WHERE status IN ('active','payment_pending')` strictly enforces that at most one open reservation exists per variant.

## Decision
- PostgreSQL is the source of truth for reservation state.
- Database transaction with partial unique index enforces single active/payment_pending reservation per variant.
- Redis distributed lock is used for fast-path concurrency control to prevent unnecessary database load during high-concurrency drop spikes.
- Cart retries for the same cart ID are idempotent and do not extend original expiration time.

## Consequences
- Single source of truth in PostgreSQL prevents double-booking.
- Clean separation between durable domain state (PostgreSQL) and short-lived lock/cache (Redis).
